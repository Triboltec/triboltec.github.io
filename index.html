🔒 Segurança
✅ Proteções Ativas
🔐 Bloqueio por tentativas — 5 erros de PIN bloqueiam a conta por 5 minutos
⏱️ Sessão automática — logout após 30 minutos de inatividade
🔑 Hash SHA-256 — PINs armazenados como hash, nunca em texto puro
🛡️ Backup restrito — somente administradores acessam backup/restauração
⚠️ Ação Necessária — Regras do Firebase
As regras do banco de dados Firebase devem ser configuradas no Console do Firebase para proteger os dados contra acesso externo.

Acesse: Firebase Console → Database → Rules
Cole as regras abaixo e publique: 
{
  "rules": {
    "erp": {
      ".read": "auth != null",
      ".write": "auth != null"
    }
  }
}
⚠️ Nota: estas regras requerem Firebase Authentication ativo. Como o sistema usa PIN próprio, para uma proteção básica use as regras abaixo enquanto não for implementado o Firebase Auth:
{
  "rules": {
    ".read": false,
    ".write": false,
    "erp": {
      "usuarios": {
        ".read": true,
        ".write": false
      }
    }
  }
}
Esta regra permite ler usuários (para o login) mas bloqueia escrita pública. Para escrita via app, use a SDK com autenticação ou contate o desenvolvedor para implementar Firebase Auth.
📋 Checklist de Segurança
✅ PINs com hash SHA-256
✅ Bloqueio por tentativas incorretas
✅ Timeout de sessão (30 min)
✅ Backup restrito a administradores
✅ Tela de setup removida do fluxo
⬜ Regras do Firebase Database configuradas
⬜ HTTPS forçado via Cloudflare (verificar)
⬜ Firebase Authentication implementado (melhoria futura)
